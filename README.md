# sEMG 팔 동작 예측 — 모델 재현 및 성능 비교 (SVM · Random Forest · XGBoost)

표면 근전도(sEMG) 5채널 신호로 **손동작 4종 × 팔꿈치 각도 2종 = 8클래스**를 동시에 분류하고, 세 모델을 같은 조건에서 비교한 실습/과제 저장소다.
데이터: [sEMG-Hand-Gesture-Elbow-Angle-Dataset](https://github.com/TestUser-alt-dev/sEMG-Hand-Gesture-Elbow-Angle-Dataset) (참가자 8명, 조건 8종, 조건당 30회 = **1,920 시행**)

---

## 1. 코드 설명

### 사용한 데이터 및 전처리
| 단계 | 내용 |
|---|---|
| 시행 분리 | CSV 1개는 30회 반복을 이어 붙인 기록. `mark` 열 기준으로 5초(5,000샘플) 시행으로 잘라 1,920 시행 구성 |
| 필터 | 60Hz 노치(Q=30) + 20~450Hz 4차 Butterworth 대역통과, `filtfilt`(영위상) |
| 분석 구간 | 시행 시작 후 **1.0~3.0초(2초)**. 슬라이드 기본값 1.5초는 RMS 포락선을 확인한 결과 동작 초반 에너지를 놓쳐서 1.0초로 변경 |
| 윈도우 | 200ms 창, 50% 오버랩 → 시행당 19개 |
| 특징 | 시간영역 5종 × 5채널 = **25차원** (RMS, MAV, WL, ZC(임계값 0.01), SSC) |
| 분할 | **시행 단위로 먼저** 층화 분할(학습 80% / 테스트 20%, 8클래스 층화, `random_state=42`) → 그 다음 각 집합 안에서 창·특징 생성. 같은 시행의 겹치는 창이 양쪽에 들어가지 않는다 |
| 표준화 | `StandardScaler`를 **학습셋에서만 fit**, 테스트에는 transform만 적용 |

학습 윈도우 29,184개 / 테스트 윈도우 7,296개 (각 클래스 균등).

### 사용한 모델
| 모델 | 설정 |
|---|---|
| SVM | RBF 커널, C=1.0, gamma='scale', ovr (기본값 위주) |
| Random Forest | 트리 100개, `random_state=42` (기본값 위주) |
| XGBoost | 트리 400개, max_depth=6, learning_rate=0.05, subsample=0.9, colsample_bytree=0.8, `random_state=42` |

> ⚠️ SVM·RF는 기본값, XGBoost만 지정 설정을 썼으므로 **완전히 대칭적인 비교가 아니다.**

### 학습 및 테스트 방법
- hold-out: 위 분할로 세 모델을 학습하고 테스트셋에서 정확도, precision/recall/F1(**macro 평균**, 실습 선택)을 계산
- 5-fold 교차검증: **시행 단위** 층화 5-fold, 폴드마다 학습 폴드에서만 scaler fit, 평균 ± 표준편차(ddof=0)
- 통계 검정: 폴드별 정확도로 대응표본 t-검정(유의수준 0.05), 참고로 Wilcoxon 부호순위 검정
- 계산 비용: 학습 시간과 1샘플 추론 시간

### 실행 방법
```bash
pip install -r requirements.txt
python main.py                 # 전체 실험 (약 10분, CPU 1코어 기준) → results/ 에 결과 저장
python extra_zc_check.py       # (선택) ZC 임계값 점검
```
데이터는 처음 실행할 때 자동으로 `git clone` 된다.

### 코드 파일
| 파일 | 설명 |
|---|---|
| `main.py` | 전체 실험 실행 (분할 → 학습 → 평가 → 교차검증 → 검정 → 결과 저장) |
| `data.py` | 데이터 로딩, 시행 분리, 필터, 윈도우, 특징 추출 |
| `model.py` | 세 모델 구성 및 학습 |
| `evaluation.py` | hold-out 지표, 혼동행렬, 5-fold CV, t-검정, 계산 비용 |
| `extra_zc_check.py` | ZC 임계값 변경 시 성능 변화 점검 |
| `results/` | 지표 CSV, `results.json`, 혼동행렬 이미지, 실행 로그 |

## 2. 모델 성능 비교

### hold-out (테스트 7,296 윈도우, macro 평균)
| Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|
| SVM | 0.4842 | 0.4975 | 0.4842 | 0.4855 |
| Random Forest | **0.6090** | **0.6102** | **0.6090** | **0.6089** |
| XGBoost | 0.5994 | 0.6001 | 0.5994 | 0.5992 |

### 5-fold 교차검증 (시행 단위, 정확도 %)
| Model | Fold 1 | 2 | 3 | 4 | 5 | 평균 ± 표준편차 |
|---|---|---|---|---|---|---|
| SVM | 47.51 | 48.22 | 49.08 | 47.94 | 49.10 | 48.37 ± 0.63 |
| Random Forest | 60.29 | 60.98 | 61.23 | 59.33 | 60.92 | **60.55 ± 0.68** |
| XGBoost | 58.74 | 59.51 | 58.21 | 59.10 | 60.27 | 59.17 ± 0.70 |

### 대응표본 t-검정 (폴드별 정확도, n=5)
| 비교 | t | p-value | 평균 차이 | Wilcoxon p |
|---|---|---|---|---|
| SVM vs RF | −45.15 | 1.4×10⁻⁶ | −12.18%p | 0.0625 |
| SVM vs XGB | −25.83 | 1.3×10⁻⁵ | −10.80%p | 0.0625 |
| RF vs XGB | 2.90 | 0.0440 | +1.38%p | 0.0625 |

### 계산 비용 (CPU 1코어 환경에서 측정)
| Model | 학습 시간 | 추론 시간 |
|---|---|---|
| SVM | 28.9 s | 1.71 ms/sample |
| Random Forest | 12.0 s | 4.98 ms/sample |
| XGBoost | 13.4 s | 1.38 ms/sample |

### 성능 분석
- **Random Forest가 hold-out과 5-fold 모두에서 가장 높았고**, 그다음이 XGBoost, SVM이 가장 낮았다. 순위는 지표(Accuracy/Precision/Recall/F1)와 폴드에 관계없이 같았다.
- SVM과 다른 두 모델의 차이(약 11~12%p)는 폴드 간 변동(약 0.7%p)보다 훨씬 커서 안정적인 차이로 보인다. 다만 RBF 커널 SVM이 이 25차원 특징에서 왜 약한지는 이 실험만으로 확정할 수 없다. (가능한 가설: 기본 하이퍼파라미터 C=1, gamma='scale'이 맞지 않음 / 트리 계열이 특징 간 비선형 상호작용과 임계 분기를 더 잘 잡음 — 둘 다 **검증하지 않은 가설**이다.)
- **RF와 XGBoost의 차이(1.4%p)는 근거가 약하다.** t-검정 p=0.044로 기준선(0.05) 바로 아래이고, 폴드 5개는 학습 데이터가 겹쳐 독립이 아니라서 p값이 낙관적일 수 있으며, Wilcoxon은 n=5에서 p가 0.0625 밑으로 내려갈 수 없어 판단 근거가 되지 못한다. "RF가 XGBoost보다 낫다"고 단정하기보다 "RF가 근소하게 높게 측정되었다" 정도로 해석한다.
- 위 비교는 XGBoost만 지정 설정, SVM·RF는 기본값이라 **하이퍼파라미터 튜닝 수준이 같지 않다.**
- 계산 비용은 추론이 가장 느린 모델이 RF, 학습이 가장 느린 모델이 SVM이었다. 측정 환경(CPU 1코어)에 따라 달라질 수 있어 순위 위주로 본다.

## 3. Confusion Matrix 분석

혼동행렬은 hold-out 테스트셋(윈도우 단위, 클래스당 912개)이다. 라벨은 `{동작}_{팔꿈치각도}` 형식이다 (데이터셋의 파일명 약어: fist, open, pro, extor).
오류는 라벨을 직접 대조해 세 종류로 분해했다. 칸 수가 다르므로 **칸당 평균**도 함께 적는다. (같은 동작·다른 각도 8칸, 다른 동작·같은 각도 24칸, 둘 다 다름 24칸)

### Model 1 — SVM
![SVM](results/confusion_SVM.png)

- 가장 잘 분류된 클래스: `fist_30` (재현율 56.0%) — 이어서 `extor_30` 55.8%
- 가장 많이 오분류된 클래스: `extor_60` (재현율 40.5%), `fist_60` (40.7%)
- 주요 오분류 유형: `extor_60→extor_30` 216건이 가장 많고, `pro_30→extor_30` 169건, `pro_30↔pro_60` 163~168건
- 오류 분해 (총 3,763건): 같은 동작·다른 각도 1,195건(칸당 149), 다른 동작·같은 각도 1,481건(칸당 62), 둘 다 다름 1,087건(칸당 45)
- 분석: 모든 클래스의 재현율이 40~56%대로 고르게 낮아 특정 클래스만의 문제가 아니라 전반적인 구분력 부족이다. 칸당으로 보면 같은 동작의 30°↔60° 혼동이 가장 잦다. 다만 SVM은 동작이 다른 오류(다른 동작·같은 각도)도 많아, 다른 모델보다 **동작 구분 자체도 약하다.**

### Model 2 — Random Forest
![RF](results/confusion_RF.png)

- 가장 잘 분류된 클래스: `pro_30` (재현율 66.0%)
- 가장 많이 오분류된 클래스: `fist_60` (재현율 56.8%)
- 주요 오분류 유형: `fist_30→fist_60` 153건, `open_60→open_30` 141건, `extor_60→extor_30` 126건, `fist_60→fist_30` 124건 — 상위 오분류 쌍이 모두 **같은 동작의 30°↔60° 혼동**
- 오류 분해 (총 2,853건): 같은 동작·다른 각도 941건(칸당 118), 다른 동작·같은 각도 1,063건(칸당 44), 둘 다 다름 849건(칸당 35)
- 분석: 상위 오분류 쌍은 전부 각도 혼동이지만, **총 오류 수만 보면 다른 동작·같은 각도(1,063건)가 더 많다.** 이는 그 칸이 24개로 많기 때문이며, 칸당으로는 각도 혼동이 약 2.7배 잦다. 또 30° 클래스(재현율 62~66%)가 60° 클래스(57~60%)보다 대체로 높았다.

### Model 3 — XGBoost
![XGB](results/confusion_XGB.png)

- 가장 잘 분류된 클래스: `pro_30`, `extor_30` (재현율 63.8%)
- 가장 많이 오분류된 클래스: `pro_60` (재현율 53.8%), `fist_60` (54.4%)
- 주요 오분류 유형: `fist_30→fist_60` 143건, `fist_60→fist_30` 136건, `open_60→open_30`·`extor_60→extor_30` 각 127건
- 오류 분해 (총 2,923건): 같은 동작·다른 각도 960건(칸당 120), 다른 동작·같은 각도 1,099건(칸당 46), 둘 다 다름 864건(칸당 36)
- 분석: RF와 거의 같은 구조다. 두 트리 계열 모델의 오류 패턴이 비슷하다는 점은 오류가 모델 선택보다 **입력 특징/데이터 쪽 한계**와 관련 있을 가능성을 시사하지만, 이 실험만으로 원인을 확정할 수는 없다.

### 오분류가 발생한 이유에 대한 해석 (가설, 검증 전)
1. **각도 혼동이 칸당 가장 잦은 것**은 팔꿈치 30°와 60°에서 같은 동작의 근육 활성 패턴이 비슷하기 때문일 수 있다. 논문도 같은 동작의 두 각도 간 혼동을 주요 오류로 설명한다.
2. 사용한 특징이 모두 **진폭·시간영역 요약치**라서 각도에 따른 미묘한 차이를 담기 어려울 수 있다. (RMS+MAV+WL만 쓰면 RF 정확도가 53.9%로 떨어진 반면, ZC를 빼도 60.6%여서 ZC는 기여가 작았다. 특징 구성이 영향을 주는 것은 확인했지만, 주파수 특징 추가 효과는 아직 실험하지 않았다.)
3. 동작별로도 오류가 적지 않으므로 각도 문제만으로는 설명되지 않는다.

## 4. 최종 결과

- **가장 성능이 좋은 모델**: Random Forest (hold-out 정확도 60.9%, F1 0.609 / 5-fold 60.55 ± 0.68%)
- **가장 성능이 낮은 모델**: SVM (hold-out 48.4% / 5-fold 48.37 ± 0.63%)
- **주요 오분류 클래스**: 같은 동작의 30°↔60° 쌍 (`fist`, `open`, `extor`, `pro`). 특히 60° 클래스들의 재현율이 상대적으로 낮았다.
- **통계 검정**: SVM과 두 트리 모델의 차이는 유의했고(p<0.0001), RF vs XGBoost는 p=0.044로 경계선이다. p값의 한계(폴드 비독립, n=5)는 위에 적었다.

### 논문과의 비교 (정직하게)
원 논문의 RF 정확도는 96.72 ± 0.58%인데 이 실험에서는 약 60.5%로 **크게 낮다.** 또 논문은 세 모델 간 차이가 모두 유의하지 않았지만 이 실험은 세 쌍 모두 p<0.05였다. 원인은 확정하지 못했다.
- 확인한 것: ZC 임계값을 0 / 0.001 / 0.01로 바꿔도 RF 정확도는 60.2 / 61.0 / 60.9%로 거의 같았다 (`results/zc_check.txt`). 즉 ZC 임계값은 원인이 아니다.
- 확인하지 못한 것: 논문의 정확한 특징 구성, 분석 구간, 분할 방식과의 차이. 이 실험의 분석 구간(1.0~3.0초), 특징 5종, 시행 단위 분할이 논문과 같은지 알 수 없다.

### 한계
1. **trial-wise 분할**이다. 학습·테스트에 같은 참가자의 다른 시행이 섞여 있으므로 이 성능은 **처음 보는 사람에 대한 성능이 아니다.** 참가자 단위 평가(LOSO)는 하지 않았다.
2. XGBoost만 지정 설정을 썼고 SVM·RF는 튜닝하지 않았다. 모델 순위가 튜닝 수준에 영향을 받았을 수 있다.
3. 5-fold 폴드는 독립이 아니고 n=5라서 p값 해석에 한계가 있다.
4. macro 평균은 실습에서 고른 방식이다 (클래스가 균등해서 accuracy와 거의 같게 나왔다).
5. 계산 비용은 CPU 1코어 샌드박스에서 측정한 값이라 다른 환경에서는 달라질 수 있다.

### 느낀 점
정확도가 높다고 더 좋은 모델이라고 말할 수는 없다는 이번 주 핵심 문장대로, RF가 1위였지만 XGBoost와의 차이는 근거가 약했고, 가장 큰 교훈은 논문 수치(96.7%)를 그대로 재현하지 못했다는 점을 숨기지 않고 보고하는 것이었다. 혼동행렬도 "인접 칸이라 이런 오류"라고 단정하지 않고 라벨을 직접 대조해 칸당 평균까지 계산해 보니, 상위 쌍만 볼 때와 총합을 볼 때 결론이 달랐다. 다음 단계로 주파수 특징 추가와 참가자 단위(LOSO) 평가를 해 볼 계획이다.
